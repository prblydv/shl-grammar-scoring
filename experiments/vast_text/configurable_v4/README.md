1. This version extends the existing experiment workflow with a third spectrogram backbone. The main notebook remains `/workspace/shl/experiments/vast_text/train_and_submit.ipynb`. New configurations containing `spectrogram_backbone` use this version; old saved configurations continue using their original implementation.

2. Select `NUM_BACKBONES=3` for text + fixed audio vectors + spectrogram. For two branches, choose `BACKBONE_PAIR='text_audio'`, `'text_spectrogram'` or `'audio_spectrogram'`. For one branch, choose `SINGLE_BACKBONE_MODALITY='text'`, `'audio'` or `'spectrogram'`. Text and audio-only behavior retains the existing model code.

3. Uncomment exactly one `SPECTROGRAM_BACKBONE` name. `cnn_tiny`, `cnn_small`, `cnn_medium` and `cnn_large` use 2/3/4/5 convolution stages with increasing channel widths. `ast_audioset` and `ast_audioset_v2` initialize from pinned AudioSet Audio Spectrogram Transformer checkpoints and fine-tune all their parameters. These are pretrained spectrogram model options, not a claim of current state-of-the-art results on SHL grammar scoring.

4. All recording frames, including silence and background sound, are used in ordered non-overlapping chunks. CNN chunks default to 256 frames (2.56 seconds); AST uses its native 1024-frame input. The last chunk is padded. CNN invalid frames are masked after each convolution and before temporal attention; AST retains native fixed-length padding semantics. Every chunk contributes through learned chunk attention with a valid-length prior. No random crop or full-recording truncation is used. Chunk boundaries reset local acoustic context.

5. CNN time encoding uses each convolution token's original recording time after downsampling, added after projection. AST retains native learned patch positions and adds absolute chunk-center time after encoding. `SPECTROGRAM_USE_TIME_ENCODING=False` disables the extra sinusoidal coordinates for either family. This consumes numerical features, not PNGs or RGB channels.

6. Per-mel-band normalization is fitted exclusively on each training fold's frames, weighted by valid sample fractions, and retained as checkpoint buffers. Full-data refit fits on all labelled training frames. AST uses mean-zero, half-standard scaling while adapting to our saved HTK log-power frontend, which differs from native Kaldi preprocessing. Exact extractor configuration, source HDF5 checksum, selected model and pinned revision are recorded. We do not pretend that saved mel arrays are identical to AST's native input frontend.

7. Automatic GPU batch probes combine the longest text with all chunks of the longest spectrogram recording. Chunk minibatches and gradient checkpointing control peak activation memory. `SPECTROGRAM_LR` applies to the complete new branch; original text/audio learning rates retain their previous behavior. The selected CNN's capacity and total/trainable parameter counts are reported.

8. CV, grouped labels, original labels including zeros, best-epoch checkpoint reload, test order, resume integrity, optional full-data refit, private model packaging and exactly two download files remain in place. Single-model packages include the new source module; loading with `random_backbone=True` builds the saved AST architecture without downloading base weights before loading the full scoring checkpoint.

9. Tests in `test_spectrogram.py` use temporary synthetic spectrograms and tiny generated text/AST models only. They cover the four CNN capacities, AST code paths, modality combinations, split-safe joins, complete chunk coverage, fold-only normalization, gradients, batch invariance, checkpoint reload, exact CV/refit resume, aligned inference, metadata exports and single-checkpoint packaging. They do not establish predictive improvement or verify pretrained-weight quality.
